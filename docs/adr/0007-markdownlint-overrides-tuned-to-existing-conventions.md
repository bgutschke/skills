# Markdown lint overrides tuned to this repo's existing conventions, not markdownlint's defaults

#31 added `markdownlint-cli2` (config in `.markdownlint-cli2.jsonc`), enforced locally by
a Husky pre-commit hook (`lint-staged`, scoped to staged `.md` files) and again in CI
(`validate.yml`). Rather than adopt markdownlint's default rule set and rewrite existing
docs to satisfy it, several rules are disabled or loosened where they fire on patterns
this repo uses deliberately: `MD013` (line length — prose here isn't hard-wrapped),
`MD018` (space after `#` — a bare issue reference like "#10 introduced..." at the start of
a paragraph is misread as an ATX heading), `MD029` (ordered-list numbering —
`skills/productivity/audit-rules/SKILL.md` numbers steps continuously across multiple H2
sections by design), `MD033` (no inline HTML — angle-bracket placeholders like
`<owner>/<repo>` are this repo's literal convention, not real HTML), `MD036` (no
emphasis-as-heading — `SKILL.md` files use bold text as compact in-list section labels),
`MD038` (no space inside code span — `skills/engineering/to-pr/SKILL.md`'s `` `type(scope): ` ``
code spans include a trailing space on purpose, to show the literal prefix), and `MD041`
(first line must be a top-level heading — `AGENTS.md` and the PR template deliberately
open with prose or a second-level heading). `MD049`/`MD060` (emphasis marker and table-pipe
style) are set to `"consistent"` rather than one fixed style repo-wide, since existing docs
already differ on both. `CHANGELOG.md` (generated by `semantic-release`, never hand-authored)
and `CLAUDE.md` (a symlink to `AGENTS.md`) are excluded from linting entirely.

## Consequences

- Every override is commented in `.markdownlint-cli2.jsonc` with its own reasoning —
  read that comment before re-enabling one; the point of each override is a real,
  named pattern this repo relies on, not a default the config happened to disable.
- `MD049`/`MD060`'s `"consistent"` style is checked per file, not repo-wide — two docs
  can legitimately use different emphasis markers or table-padding styles without either
  being flagged. A clean lint run is not evidence of one house style across every file.
- The overrides are tuned to *today's* conventions. A genuinely new pattern this repo
  hasn't adopted yet (e.g. hard-wrapped prose) won't be flagged as inconsistent by
  `MD013` either — disabling a rule removes its coverage entirely, it doesn't pin the
  ruleset to whatever "correct" looked like on 2026-08-24.
